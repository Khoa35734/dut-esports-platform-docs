## Nguyên nhân chạy dev và bản sửa

1. Tại `D:\DUT ESPORTS`, ban đầu không có `package.json`: `npm.cmd run dev` báo ENOENT. Script `Web-giai-dau` chỉ chạy backend; chạy riêng frontend không đảm bảo API cũng lên. Thêm root runner khởi động cả hai, giữ script riêng, dừng child khi một service thất bại và xử lý Windows process tree.
2. PowerShell chặn `npm.ps1`: lệnh `npm` thất bại vì execution policy. Dùng `npm.cmd`, không sửa policy máy.
3. API clients trước đây suy ra `<hostname>:5000` và protocol từ browser, có thể gọi HTTPS vào backend HTTP hoặc port không đúng. Dùng `/api` cùng origin và Next rewrite tới `API_PROXY_TARGET`, vẫn hỗ trợ override env cũ.
4. Backend bind rõ `HOST` mặc định `0.0.0.0`, `PORT` mặc định 5000; log URL localhost và lỗi port bận. Next giữ `-H 0.0.0.0`. Không dùng `0.0.0.0` làm URL browser.
5. Build thật bị lỗi/treo tải Montserrat từ Google trong môi trường mạng này. Font chính thức được đóng gói cục bộ, sau đó build production exit 0. Không tắt kiểm tra build hoặc thay font khác.
6. Supabase DNS/connection có lúc thất bại trong môi trường kiểm tra; liveness không còn phụ thuộc DB. DB probe trả lỗi kiểm soát, UI hiển thị retry, không che lỗi bằng dữ liệu giả. Có lần probe 500 rồi lần sau 200; không chứng nhận DB luôn ổn định.

Cache Next cũ được di chuyển bảo toàn vào `artifacts/next-dev-backup-20261010`; không xóa. Sau build đã tái hiện dev treo ở “Starting” với cache production; chuyển cache đó sang `artifacts/next-after-build-20261010` và chạy lại cho “Ready in 2.2s”. Next config tách `.next-dev` cho development và `.next` cho production để tránh lặp lại. Không có đủ bằng chứng để coi cache là nguyên nhân duy nhất của lỗi ban đầu.

Backend startup preflight nay chỉ đọc metadata: bỏ ALTER/UPDATE tự động trên `registration_members` mỗi lần chạy. `schema:check` cũng không thay đổi DB. Không đưa secrets vào báo cáo/log mới; không echo query/token/exception trong middleware và database probe.

## Cách mở ứng dụng và điều kiện còn thiếu

```powershell
cd 'D:\DUT ESPORTS'
npm.cmd run dev
```

- Frontend: http://localhost:3000 — màn P02: http://localhost:3000/tournaments.
- API trực tiếp: http://localhost:5000/api/health; qua proxy: http://localhost:3000/api/health.
- LAN: `http://<IPv4-máy-chạy>:3000`, cùng mạng và firewall cho TCP 3000. Chưa thử trên thiết bị LAN thật.
- Camera/GPS mobile cần HTTPS và chứng chỉ tin cậy; có `dev:https`, chưa nghiệm thu camera/GPS hoặc Safari/Chrome Android.
- Không sửa env thật. Backend cần Supabase connection/JWT cấu hình hợp lệ; env mẫu mới không chứa secret thật.

Lần khởi động cuối sau build: root `npm.cmd run dev` báo **Ready in 2.4s**, API listen `0.0.0.0:5000`, PostgreSQL kết nối thành công. Request HTTP sau restart: `/`, `/tournaments`, `/api/health`, `/api/db-test`, `/api/tournaments?public_only=true` đều **200**; `/api/admin/stats`, `/api/checkins` không đăng nhập đều **401**. Dev server được giữ chạy để người dùng mở ứng dụng; lỗi DB gián đoạn ở những lần trước vẫn là giới hạn cần theo dõi.

Các blocker cần xử lý tiếp: public registration tạo admin, tài liệu KYC thiếu signed authorization, public list chưa enforce filter server-side cho mọi caller, audit permissions sai; lifecycle trạng thái legacy và domain canonical cần kế hoạch tương thích. Thay đổi core RBAC/migration/state machine cần đặc tả review theo AGENTS §11. Cấu hình tile provider và điều kiện tự cấp certificate CTV còn ghi NEEDS_STAKEHOLDER_CONFIRMATION trong tài liệu; không tự chốt quy tắc.

Không chạy production migration, không seed/tạo người dùng thật, không kiểm thử dữ liệu cá nhân thật, chưa có E2E đầy đủ với tài khoản từng role và mọi workflow. Các kết quả đó được ghi là chưa kiểm tra, không báo pass.
