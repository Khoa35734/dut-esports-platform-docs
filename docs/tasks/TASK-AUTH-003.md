TASK-ID: TASK-AUTH-003
Title: Verify and enforce password hashing Argon2id/bcrypt >= 12 requirement

Goal:
Audit and verify password hashing across all registration, authentication, profile update, and account recovery endpoints, guaranteeing strict enforcement of bcrypt cost >= 12 (or Argon2id) per NFR-SEC-06 and AGENTS.md § 2.4, ensuring seamless upgrade of legacy cost-10 hashes and zero leakage of password hashes in responses, logs, or error messages.

Requirements:
SRS 5.1 (Auth Security & Password Hashing), NFR-SEC-06 (Bcrypt cost >= 12 / Argon2id), AGENTS.md § 2.4 (Password Confidentiality).

Conflict IDs:
RC-SEC-001

Current Behavior:
1. `studentRegister`, `register`, `updateParticipantProfile`, and `resubmitParticipant` have been upgraded to `bcryptjs.hash(password, 12)`.
2. `studentLogin` and `login` include auto-migration logic to upgrade cost-10 hashes to cost-12 on successful login.
3. Need to audit all repositories and controllers to guarantee that no raw or cost < 12 hashing calls remain and that password hashes are never serialized in API responses.

Target Behavior:
1. Universal Cost Factor >= 12:
   - Every hashing operation across all endpoints strictly enforces `cost >= 12`.
2. Hash Confidentiality:
   - `password_hash` column is excluded from all `SafeUser` and `SafeParticipant` queries.
   - No log statements output passwords or hashes.
3. Automated Unit & Integration Tests:
   - Dedicated test suite validating cost >= 12 generation, legacy hash auto-upgrade, and response payload sanitization.

Scope:
- `Web-giai-dau/backend/src/controllers/auth.ts`
- `Web-giai-dau/backend/src/repositories/user.repository.ts`
- `Web-giai-dau/backend/src/repositories/participant.repository.ts`
- `Web-giai-dau/backend/tests/auth.test.ts`

Out of Scope:
- Changing hashing algorithm to Argon2id (Bcrypt cost 12 already fulfills NFR-SEC-06 without adding binary node-gyp dependencies).
